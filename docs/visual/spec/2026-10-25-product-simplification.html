Spec

TL;DR

Trzy uproszczenia. rerun znika z CLI, API i pluginu: przycisk „Rerun” w webie zostaje, ale po prostu startuje nowy run z tymi samymi ustawieniami. Unstable i Agent errors łączą się w jedną sekcję „Problemy” na stronie Evaluation i jedną komendę CLI. Limit porównania to limit wydruku: 7 runów — tyle obejmuje compare, otwarcie porównania i jeden sweep.

Zostają bez zmian: grupy runów i sweep (eval na kilku modelach), wydruk do PDF (pokazanie wyników z lokalnej instancji), filtr usage w Versions.

Scenariusze

  1. Rerun w webie

    Na stronie runu 7b4d9afd (tag smoke) Piotr klika „Rerun”. Startuje nowy run tego agenta z tym samym tagiem, endpointem i grupą — jak dziś, ale przez zwykły start runu. Przechodzi na stronę nowego runu.

  2. Rerun z Claude Code

    Claude chce powtórzyć run: używa suwageval run --tag smoke --wait (tagi zna z results). suwageval rerun kończy się błędem „unknown command”; skill run i dokumentacja mówią, jak to zrobić przez run.

  3. Co jest nie tak z agentem

    Na stronie Evaluation sekcja „Problemy” ma dwie listy: niestabilne checki (z wersją i liczbą przebiegów) i scenariusze z błędem agenta. W CLI jedna komenda wypisuje oba, z --json.

  4. Sweep na 9 modelach

    suwageval sweep z 9 wariantami odmawia przed startem: „at most 7 variants in one sweep: pick them with …”. Dwa sweepy po 4–5 wariantów działają i każdy otwiera się i drukuje w całości.

  5. Porównanie 8 runów

    suwageval compare z 8 id (albo grupa z 8 runami) → błąd z limitem 7; web pozwala zaznaczyć najwyżej 7 runów do porównania.

Kryteria akceptacji

  • „Rerun” na stronie runu startuje nowy run z tymi samymi tagami, endpointem i grupą i otwiera jego stronę (e2e)
  • suwageval rerun nie istnieje; trasa /rerun nie istnieje (EveryEndpointHasACliCommandTests bez niej)
  • Plugin, front-doors.md i README nie wspominają o rerun jako komendzie
  • Strona Evaluation ma sekcję „Problemy” z niestabilnymi checkami i błędami agenta; osobnych stron nie ma, stare adresy prowadzą do niej
  • Jedna komenda CLI wypisuje niestabilne checki i błędy agenta (tekst i --json)
  • compare (CLI, API, web) przyjmuje najwyżej 7 runów; ten sam limit co wydruk, pilnowany testem
  • sweep z więcej niż 7 wariantami odmawia przed startem czegokolwiek
  • Bramka i e2e zielone

Ryzyka

Zmiana łamiąca CLI i API: skrypty z suwageval rerun, unstable, agent-errors albo porównaniem więcej niż 7 runów przestaną działać. Ten epik i tak łamie CLI (adresy /eval), więc wchodzi w to samo ogłoszenie przed merge.

7 to dzisiejszy limit wydruku porównania (PRINT_MAX_RUNS). Jeśli wydruk zmieni limit, porównanie i sweep idą za nim.
